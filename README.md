# TetraFree

Десктопное приложение для совместной разработки с ИИ-агентами: чаты с агентами, версии с диффами и откатом, живое превью, задачи, документы, CI-пайплайны, память проекта и режим дизайна.

Стек: **React 18 + TypeScript (strict) + Vite 5**, состояние — zustand + immer (с сохранением в localStorage), анимации — framer-motion, терминал — xterm.js, десктоп-оболочка — **Tauri 2**.

## Запуск

```bash
npm install
npm run dev          # веб-режим: http://localhost:3000
npm run build        # проверка типов + прод-сборка в dist/
```

### Десктоп (Tauri 2)

Нужны Rust и системные зависимости Tauri: https://tauri.app/start/prerequisites/

```bash
npm run desktop:icons   # сгенерировать иконки из public/logo.png (лучше подложить 1024×1024)
npm run desktop:dev     # окно приложения с hot reload
npm run desktop:build   # установщик под текущую ОС
npm run desktop:build:full     # + автообновление (нужны ключ подписи и tauri.updater.conf.json; релизы собирает .github/workflows/release.yml)
npm run desktop:build:extras   # то же + автозапуск, значок в трее, глобальная клавиша Ctrl+Alt+N (см. src-tauri/src/extras.rs)
```

Окно без системной рамки — свой тайтлбар с перетаскиванием, свернуть/развернуть/закрыть. Внешние ссылки открываются в системном браузере через `plugin-opener`.

## Первый запуск

В приложении нет демо-проектов, демо-моделей и заготовленных ответов — только то, что ты подключил сам.

1. **Войди или зарегистрируйся** (нужен сервер: в десктопной сборке он стартует сам).
2. **Подключи модель:** Настройки → Провайдеры → ключ Anthropic / OpenAI, любой OpenAI-совместимый API или локальная Ollama. «Загрузить список у провайдера» берёт актуальные модели из `GET /models`, «Проверить» делает настоящий запрос. Пока модели нет, агенты не отвечают.
3. **Заведи проект:** «Новый проект» (родительская папка + имя, `Обзор…` открывает выбор папки на диске) или «Открыть папку» — существующий код читается в проект как есть, ничего не удаляется и не перезаписывается.

## Что настоящее

Всё. Файлы проекта лежат в выбранной папке на диске; терминал — настоящий shell в этой папке; git — настоящий git; шаги пайплайнов — настоящие команды; ответы агентов — ответы выбранной модели; почта, аккаунты, приглашения и командная синхронизация идут через `server/`.

Что не работает без сервера (в десктопной сборке он запускается сам): папка на диске, терминал, пайплайны, git. Браузерный режим без сервера хранит файлы только внутри приложения.

## Бэкенд и диск

- `npm run dev` поднимает Vite со встроенным бэкендом (тот же origin). Отдельно: `npm run server` → `http://127.0.0.1:3001` (`PORT`, `HOST`, `TF_ROOT` — переменные окружения).
- **Папка проекта — любая, которую ты выбрал** (путь хранится в проекте). Проекты, созданные до 2.0, остались в `~/TetraFree/projects/<имя>` — их путь определяется при первом открытии. Каждая версия — git-коммит (если git установлен); в существующей папке без git он создаётся при первой синхронизации.
- Чтение существующей папки ограничено: текстовые файлы до 1 МБ, не более 2500 файлов и 4 МБ в сумме (хранилище приложения — localStorage); `.git`, `node_modules`, `dist`, `target`, `.venv` и подобное пропускаются, плюс всё, что исключает корневой `.gitignore` (упрощённый разбор: имена, `dir/`, `*.ext`, `/путь`; отрицания `!` не учитываются). Если упёрлись в лимит, приложение предупреждает и не считает непрочитанное удалённым.
- Синхронизация трёхсторонняя (store ↔ диск ↔ база последней синхронизации). Внешние правки (редактор, `git pull`) подхватываются раз в 2,5 с и сохраняются версией «Правки с диска». Включается/выключается в Настройки → Бэкенд и диск.
- **Терминал — настоящий PTY** (Windows: ConPTY через помощник на C#, собирается штатным `csc.exe`; Linux/macOS: нужен `python3`): интерактивные программы (vim, htop, ssh, `npm create`, ввод паролей), история и Tab‑дополнение самого shell, цвета, ресайз окна, сеанс живёт, пока не закрыт, — панель можно скрывать и открывать. Транспорт — обычный HTTP (вывод потоком, ввод и ресайз POST‑ами), без нативных модулей. Файлы, изменённые в терминале, сами подхватываются в проект. Без PTY — запасной режим: каждая команда отдельным процессом в настоящем shell (Ctrl+C прерывает, `cd` запоминается, stdin недоступен).
- Без бэкенда терминала, пайплайнов и папки на диске нет: приложение честно говорит об этом, а не имитирует.
- Десктоп (Tauri): `server/tetra-server.mjs` входит в ресурсы, при старте запускается `node` из PATH. Нет node или порт занят — приложение работает как офлайн/с уже запущенным сервером. Сборка в песочнице не проверялась (там нет Rust).

## Агенты

- Агент работает только с настоящей моделью (Настройки → Провайдеры). Режим «builder» пишет код, «designer» — макеты; это один и тот же провайдер с разным системным промптом.
- Протокол живого агента: `<write>`, `<edit>`, `<delete>`, `<rename>`, `<read>`, `<run>`. Код в чат не попадает: вместо него карточки файлов (создаёт/редактирует/удаляет, +N/−M, раскрываемый дифф); файлы печатаются в панели кода в реальном времени (глазок «Следить»).
- Автономность: «Тихо/Уведомить» применяют всё; «Спросить» предлагает удаления и переименования (Применить/Отклонить); «Эскалация» предлагает всё и запрещает `run`.
- Один ход = одна версия; «Откатить» возвращает все файлы хода, включая удалённые.

## Режим дизайна

Реальные `site/*.html` на холсте (desktop/tablet/mobile), выделение, перетаскивание, ресайз, двойной клик — правка текста, инспектор и CSS‑переменные `:root`. Подрежимы: Холст / Превью / Код. Любая правка пишется в файл, правка файла обновляет холст; Undo/Redo. В AI‑панели — выбор модели и контекст выделенного элемента.

## Аккаунты и безопасность

Вход требует сервера (`npm run dev` или `npm run server`). Без сервера доступен «локальный режим» — без аккаунта, команд и приглашений.

- **Регистрация** → письмо с 6-значным кодом (15 минут, 5 попыток) → почта подтверждена → вход. Код можно ввести или перейти по ссылке из письма.
- **Пароли:** scrypt, минимум 8 символов, отсеиваются популярные пароли и пароли с частью почты/имени; индикатор надёжности и подсказка Caps Lock.
- **Вход:** одинаковая ошибка для неверной почты и пароля (нет перебора адресов), блокировка на 15 минут после 5 неверных паролей, лимиты по IP и по адресу, письмо о блокировке.
- **Сессии:** случайные токены (на сервере хранится только sha256), «запомнить на 30 дней» или 12 часов неактивности; список устройств, завершение одной/всех остальных, автоматический выход при отзыве.
- **Сброс пароля:** код на почту; после сброса все сессии завершаются, приходит уведомление.
- **2FA (TOTP, RFC 6238)** + 8 одноразовых резервных кодов; QR-код для приложения‑аутентификатора (свой генератор, проверен декодером) или ввод ключа вручную.
- **Журнал безопасности** (входы, неудачные попытки, смена пароля, 2FA, приглашения), **удаление аккаунта**.
- **GitHub / Google:** кнопки появляются, когда заданы `GITHUB_CLIENT_ID/SECRET` или `GOOGLE_CLIENT_ID/SECRET` (см. `.env.example`). Не проверялось с реальными ключами.
- Диск, shell, git и прокси к моделям доступны **только с localhost и только вошедшему** пользователю; превью — по подписанному токену сессии.

## Почта

- Без настройки письма не уходят в интернет: на экране входа есть **«Dev-почта»** — там видны все письма, а код подставляется одной кнопкой (виден только на localhost и только без SMTP).
- Реальная отправка: `SMTP_URL=smtps://user:pass@host:465` (или `smtp://…:587` со STARTTLS), `MAIL_FROM`, `APP_URL`. Клиент SMTP свой, без зависимостей; с живым SMTP‑сервером не проверялся.

## Команда и приглашения

1. Владелец: Настройки → Участники → почта → «Пригласить». Проект загружается в облако сервера, человеку уходит письмо со ссылкой (7 дней, только для этой почты; можно отозвать и отправить заново).
2. Приглашённый открывает ссылку, регистрируется/входит с той же почтой и принимает приглашение — проект появляется у него целиком (файлы, документы, задачи, чаты, память). Входящие приглашения видны и на лаунчере.
3. **Синхронизация в реальном времени.** Сервер держит поток событий (SSE) на каждый открытый облачный проект: чужая правка или перемещение курсора доходит за доли секунды; запасной вариант — опрос раз в 5 с. Свои правки уходят через ~0,7 с.
4. **Совместное редактирование файла.** Кнопка «Править» в панели кода открывает редактор (Tab, автоотступ, Ctrl+/ — комментарий, Ctrl+S). Правки двух людей в одном файле сливаются **построчно (diff3, как в git)**: если правили разные места — сольётся молча и курсор останется на месте; если одну и ту же строку — появятся маркеры `<<<<<<<`/`=======`/`>>>>>>>` и кнопки «мои / чужие / обе». Пока маркеры не убраны, файл в облако не уходит (коллегам ломаться нечему). Если общего предка нет (первый запуск после очистки браузера) — обе версии сохраняются (`файл.cloud`). Видно, кто в каком файле и на какой строке (цветная полоса и метка), есть **комментарии к строкам** (клик по номеру), они общие и «прилипают» к тексту строки при сдвиге. Это не CRDT: слияние происходит между синхронизациями, а не посимвольно.
5. **Общее:** файлы, документы, задачи, чаты, память, окружение, **лента версий** (вкладка «Команда» в «Истории версий»), **запуски деплоя**, комментарии. **Удаления не воскресают:** при удалении документа/задачи/чата/заметки/комментария ставится «надгробие» (хранится 90 дней), слияние сравнивает его с временем последней правки — правка после удаления побеждает. Одинаковые номера задач, созданных одновременно, переназначаются.
6. **Остаётся локальным:** снимки версий (rollback возможен только к своим версиям; чужие видны в ленте как запись), позиции прокрутки, черновики. Документы синхронизируются целиком (последняя правка выигрывает).
7. Командный хост: `npm run build && HOST=0.0.0.0 TF_ALLOWED_HOSTS=tetra.example.com APP_URL=https://tetra.example.com npm run server` — сервер сам отдаёт приложение. Диск и терминал на удалённом хосте отключены намеренно.

## Агент: очередь, проверка, правила

- Пока агент работает, новые сообщения встают в **очередь** (можно убрать или нажать «Сейчас» — остановит и отправит). Следующее уходит само после хода.
- **Проверка правок:** после правок живой модели запускается `typecheck`/`lint`/`test` из `package.json` (или `py_compile`/`node --check`); если падает — агент один раз сам исправляет. Выключается в Настройки → Бэкенд и диск.
- **Правила проекта:** файл `.tetra/rules.md` читают все агенты перед работой.
- Под ответом живой модели — оценка токенов хода.

## Что не сделано

- Английский язык.
- Проверка Tauri‑сборки, SMTP и OAuth на живых сервисах (в песочнице нет Rust, почтового сервера и ключей).
- CSP для десктопа: превью дизайна рендерится через `srcdoc` со скриптами, а такие документы наследуют CSP приложения — строгая политика их сломает. Сначала нужно отдавать превью с сервера.
- PTY на Windows (ConPTY).
- Документы без посимвольного слияния; снимки версий коллег не передаются по сети.
