## Что найдено

[Реестр](inventory.json) содержит **77 записей-наблюдений**, а не «77 независимо воспроизведенных багов»: 75 сценариев/кодовых замечаний в шести областях и 2 затронутые dev-зависимости. Общие причины помечены `root_group`; две очевидные пары-дубликата — ST-10/D-01 и UI-03/UI-04. Связанные отмена/очереди/process-tree также сгруппированы. **Не все записи подтверждены production E2E:** у каждой области отдельно указаны реальное исполнение, mock/model, статический код и непроверенные гипотезы. Гипотезы из дополнительных разделов в счет 77 не входят. Приоритет — ущерб в указанном сценарии, не измеренная частота.

## Что действительно проверено

- Полный `npm run check`: **75 серверных + 251 клиентский тест, 326 pass / 0 fail**; TypeScript, ESLint и существующий format-check успешны.
- `npm run build` успешен. Проверки повторены после сброса среды.
- Повторены реальные UI-сценарии по переходам проектов/удалению/клавишам и компонентные Design-пробы; 7 сценариев без ошибок harness. Их результаты демонстрируют дефекты, не успешное исправление.
- Случайный UI-прогон: сначала 187 действий (одна ожидаемая validation HTTP400), затем **284 действия, 0 зарегистрированных ошибок**. Random run не опровергает детерминированные потери данных и не является проверкой всех функций.
- В отдельных областях выполнялись дополнительные mock/native-fixture проверки. Их existing tests — подмножества общего набора, **не суммировать** с 326. Точное ограничение первоначального агентного набора (16 pass / 1 fail) сохранено, полный успех не заявляется.
- `npm audit --json`: 2 affected dev packages, esbuild moderate и vite high. Это advisory matches, не воспроизведенная атака на установленную Tauri сборку.

## Очередь исправлений

1. **P1: проектная идентичность и жизненный цикл editor/callback.** pid+path/docId должны переживать await/cleanup; импорт и копия по умолчанию отвязаны от чужих папок/облака.
2. **P1: durable checkpoint и безопасные миграции.** Общая транзакционная generation для state/bases/ancestors; неподдерживаемая версия не должна уничтожать данные; recovery не выбирает старую копию.
3. **P1: сохранение обеих сторон конкурирующих правок.** CAS по revision/hash, three-way или конфликтные копии; stale delete/rename/revert нельзя подтверждать прежней карточкой молча.
4. **P1: отмена и approved-spec execution.** Controller generation; precheck всех tool effects; prompt/tier/pid должны совпадать с одобрением автоматизации.
5. **P1/P2: серверные границы.** Единый final-path containment, registration transaction ownership, обязательный TLS для authenticated SMTP, явная 2FA-policy. Preview изолировать по origin, не только URL path.
6. **Windows gate до тега.** Native PowerShell/cmd PTY execution+resize+exit, process trees, updater failure recovery, installed bundle без системного Node; CI и Release должны проверять тот же SHA.
7. Остальные P2/P3: CRLF resolution, vault/backend identity и idle-loop, queue consistency, протокол MCP, regex timeout, dependency migration, diagnostics и reproducibility.

Каждое исправление закреплять регрессией, ожидающей безопасный результат противоположно текущим defect probes. Выпускать исправления небольшими проверяемыми пакетами, а не одним неподконтрольным массовым rewrite.

## Ограничения и честный статус

**Исправления не применены.** В репозитории добавлена только документация аудита, не новая версия приложения/релиз/тег.

Не проверены настоящие Windows/Tauri/WebView2/DPAPI, installer/updater artifacts, реальные OAuth/SMTP/model providers, два настоящих cloud-клиента, power-loss и native browser-IDB quota/upgrade integration. Исправление STARTF_USESTDHANDLES уже присутствует и не выдается за новый отсутствующий патч; его нативная работоспособность этим аудитом не подтверждена.

После паузы пользователя среда сбросилась: первоначальные локальные harness-файлы и часть логов исчезли. Отчеты восстановлены из сохраненного журнала; ключевой UI, check/build и dependency audit повторены. Утрата исходного лога не заменяется заявлением о повторно выполненном тесте. Ссылки на старые локальные harness-paths в исторических отчетах описывают методику; эти файлы не обещаются как приложение к commit.

Это широкий глубокий проход с приоритизированными доказательствами, **не гарантия «найдены все баги» и не шесть часов непрерывного исполнения**. Рабочие exploit-пейлоады и цепочки захвата/извлечения токенов в публичный отчет не включены.
