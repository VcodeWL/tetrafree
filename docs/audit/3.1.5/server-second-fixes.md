## Frontend/API contracts

MCP `/status` server fields add `hash:string`, `runningHash:string|null`, `overrides:string[]`, optional `missing:true` for still-running configuration removed from disk. `/approve {server,approved?,expectedHash}` requires exactly shown hash for approval; stale confirmation409. Revoke and `/stop {server,expectedHash}` can target the displayed older running hash. No silent fallback approval if hash omitted. Env/header values hidden unless a plain `${VARIABLE}` reference; URL credentials/query values and recognized secret CLI flags redacted. Missing-card display is captured from raw approved presentation, never from expanded runtime credentials.

Sensitive auth body fields: `stepupCode` (TOTP/recovery), `password` (fresh current password when no enabled MFA), `emailCode` (OAuth-only without MFA). Password-change still takes `old` and new `password`, plus `stepupCode` if MFA enabled or `emailCode` if OAuth-only/no-factor. API 403 step-up response contains `{need:'stepup',method:'totp'|'password'|'email'}`. AccountPanels provides controls, including `/stepup/email` send action. Enable-new-factor continues to require newly configured TOTP code; setup already required fresh proof.

Public error helper exports `publicError(status,message,extra)` and `publicFailure(error,fallback,status,scope)->{status,error}`. Parent/process agent use same helper. New runtime resource only `server/public-errors.mjs` (parent confirmed added).
