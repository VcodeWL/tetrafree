# TetraFree 3.5.0 — приёмка интерфейса

## Объём

Серо-сиреневая палитра в двух темах, исходная фотография фона, декоративная лента ввода 6 px с бесшовным циклом 12 s, общая кнопка, упрощённые старт/чат/навигация, новый знак проекта с сохранением собственных иконок. По независимому разбору дополнительно исправлены клавиатурная безопасность дизайна, навигация общих меню и переполнение узких экранов.

Это приёмка исходников и браузерного интерфейса в Linux Chromium, не установленного Windows-приложения. Тестовые проекты созданы только в изолированных браузерных контекстах; внешние запросы и `/api/` в визуальных сценариях заблокированы. Отправка реальной модели, оплата, синхронизация и операции Windows этим прогоном не подтверждались.

## Проверки

- `npm run check`: TypeScript, ESLint, форматирование; 184 Node-теста и 772 TypeScript-теста, всего **956 passed / 0 failed**.
- `npm run build`: успешно.
- `npm audit`: 0 известных уязвимостей на момент проверки; lockfile зависимостей не обновлялся, кроме версии корневого пакета.
- Браузерный acceptance: **25/25**, без pageerror. Тёмная/светлая темы, поле ввода, disabled-состояние, панель файлов, настройки, компактность, 1100 px и 390 px, меню боковой панели, список проектов.
- Отдельная клавиатурная приёмка: **10/10**. Фокус меню, стрелки/Home/End, Enter/Space, Escape с возвратом фокуса, Tab; Delete в confirm, меню и вне дизайна не изменяет файл; обработанный Delete игнорируется; обычный Delete выбранного слоя и Undo работают.
- В проверенных сценах axe WCAG A/AA не обнаружил нарушений. Это не сертификат доступности всего приложения: скринридер и все комбинации экранов не проверены.
- Лента действительно движется без сдвига layout; при системном/пользовательском reduced motion статична. В скрытой вкладке анимация приостанавливается. Однотонный режим скрывает ленту, выключение фонового изображения не меняет акценты.
- PNG знака проекта восстановим из base64 manifest, 128×128 с прозрачностью. Визуально проверен на 16/24/32/64 px в обеих темах. Исходный файл фонового изображения не менялся.

## Исправления по независимому аудиту

1. **P1: Delete под подтверждением удалял выбранный узел из HTML-файла.** Проверяется актуальный UI-контекст, наличие модалки/палитры/меню, фокус внутри Studio, editable-контролы, IME и defaultPrevented. Повторено с реальным confirm и реальным меню вставки; исходный HTML сохраняется. Обычное удаление слоя и Undo не сломаны.
2. **P1: общие меню нельзя было использовать с клавиатуры.** При открытии фокус на выбранном/первом доступном пункте; стрелки, Home/End, Enter/Space, Escape и Tab реализованы. Disabled-пункты пропускаются и не активируются.
3. **Узкий launcher:** действия и метаданные переносятся; при 390 px document.scrollWidth = 390. Все четыре действия доступны.
4. **Узкий дизайн:** центр canvas/code больше не сжимается до нуля. Минимальная рабочая ширина 300 px, горизонтальная прокрутка внутри рабочей области. Это функциональный fallback, не законченный mobile-first редактор. Нативный минимум окна приложения остаётся отдельным ограничением.

## Ограничения и следующий этап

- Нативная сборка Windows, Rust, sidecar, файловые диалоги, установка и обновление в этом окружении не проверены. Известное падение Windows smoke 3.4.0 этим визуальным этапом не считается исправленным. До нативной приёмки не ставить тег и не публиковать релиз.
- Полный независимый разбор и оставшиеся проблемы — `docs/UI_REVIEW_3_5.md`. Автоматические проверки не подменяют usability-тестирование.
- PRO — только следующий дизайн-концепт из ROADMAP. В приложении не добавлены выдуманная подписка, платные возможности, счёт или статус оплаты.
