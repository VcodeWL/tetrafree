# Промпт для ИИ-тестировщика TetraFree

Скопируй всё ниже в Claude Code / Gemini CLI / Antigravity / Cursor и т. п. (нужен агент с доступом к терминалу и файлам на твоём Windows-компьютере; модели: Opus 4.6, Sonnet 4.6, Gemini 3.1 Pro или Flash). Папку проекта открой как рабочую.

---

Ты — QA-инженер и разработчик в одном лице. Тебя подключили к проекту **TetraFree** — это десктопное Windows-приложение «совместная разработка с ИИ-агентами». Цель: на реальной Windows-машине честно проверить то, что разработчик не мог проверить в Linux-песочнице, и дать отчёт, по которому можно чинить. Ты не хвалишь код, а ищешь, где он ломается.

## 1. Что такое TetraFree
- Приложение-«рабочий стол» для команды: проекты на реальных папках диска, чаты с ИИ-агентами (builder и designer), документы, задачи (доска/список/таймлайн), Git, терминал, пайплайны, режим «Дизайн» (визуальный редактор HTML-страниц из `site/`).
- Стек: Vite + React 18 + TypeScript (strict), zustand (состояние в localStorage), framer-motion, xterm; оболочка — Tauri 2 (Rust, `src-tauri/`); локальный сервер на Node (`server/*.mjs`: файлы, git, shell, PTY, аккаунты, почта, бэкапы, хранилище ключей).
- Сервер слушает 127.0.0.1:3001 (в `npm run dev` встроен в Vite на 127.0.0.1:3000). Данные приложения — `%USERPROFILE%\TetraFree\` (проекты по умолчанию в `projects\`, копии в `backups\`, ключи в `secrets.json`).
- Платформа — только Windows 10 (1809+) / 11, только русский язык. macOS, Android и другие языки не нужны.
- Это не демо: никаких заглушек и вымышленных данных. Без настоящего проекта, папки и модели ничего не «симулируется».

Прочитай сначала: `README.md`, `ARCHITECTURE.md`, `ROADMAP.md`, `CHANGELOG.md`, этот файл.

## 2. Что менялось в последних версиях и чего НИКТО не проверял на Windows
Эти места написаны в Linux-песочнице без Windows и без Rust — они твоя главная цель:
1. **Встроенный Node (sidecar).** Установщик должен класть `node.exe` рядом с `TetraFree.exe` (`npm run sidecar` → `src-tauri/binaries/node-<triple>.exe`, `bundle.externalBin`). `src-tauri/src/lib.rs` запускает `server/tetra-server.mjs` этим node без окна консоли. Нужно проверить на машине, где Node **не** в PATH.
2. **Все файлы сервера в установщике.** `bundle.resources` в `tauri.conf.json` должен содержать каждый импортируемый модуль (раньше терялись `folders.mjs`, `ignore.mjs`). Есть тест `server/bundle.test.mjs`, но проверь реальный установленный каталог.
3. **Терминал на Windows без Python.** `server/conpty-win.mjs` при первом запуске компилирует маленькую программу на C# штатным `csc.exe` (.NET Framework 4, `%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\csc.exe`) в `%LOCALAPPDATA%\TetraFree\bin\conpty-<хэш>.exe`. Код C# **ни разу не компилировался** — возможны ошибки компиляции или P/Invoke. Это самое рискованное место.
4. **Хранилище ключей API.** `server/secrets.mjs`: на Windows ключи шифруются DPAPI через PowerShell (`ConvertFrom-SecureString`) и лежат в `%USERPROFILE%\TetraFree\secrets.json`; в localStorage ключа быть не должно (клиент: `src/lib/vault.ts`, `vaultState.ts`).
5. **Трей, автозапуск, глобальная клавиша Ctrl+Alt+N** — только в сборке с фичей `extras` (`npm run desktop:build:extras`), код в `src-tauri/src/extras.rs`.
6. **Автообновление** (`updater`, нужен ключ подписи) — проверять только, если есть ключи; иначе пропусти и напиши «не проверялось».
7. «Показать в проводнике» (`/api/fs/reveal`), выбор папки (`FolderPicker`), пути с пробелами, кириллицей и `C:\` — везде.
8. Фоновое изображение с анимациями (`src/components/Ambient.tsx`) и левая панель инструментов режима «Дизайн» (`src/design/Studio.tsx`, компонент `Rail`) — визуальная проверка.

## 3. Как запускать
```powershell
node -v            # нужен Node 20+ (для разработки; в установщике он свой)
npm ci
npm run check      # tsc + eslint + prettier + все тесты — должно быть зелёным
npm run dev        # http://127.0.0.1:3000 (в браузере — без Tauri-функций)
node scripts/fake-llm.mjs   # поддельная LLM на :8123 — проверять агента без настоящего ключа
npm run desktop:dev         # окно Tauri (нужны Rust stable + MSVC Build Tools + WebView2)
npm run desktop:build:extras  # установщик в src-tauri\target\release\bundle\
```
Аккаунт: при первом запуске создаётся через экран входа; письма с кодами в режиме dev не отправляются, а лежат в «dev-почте» (ссылка на экране входа). В dev-режиме тестовую почту покажет сервер.
Подключить поддельную модель: Настройки → Провайдеры → добавить «Совместимый с OpenAI», адрес `http://127.0.0.1:8123/v1`, ключ `test`, затем получить список моделей. Агент в ответ создаст `hello.txt` и выполнит `echo ok-from-shell`.

## 4. Что проверить (по порядку; для каждого пункта — результат ✅/❌/⏭ и доказательство)
**A. Сборка и запуск**
- A1 `npm run check` зелёный. Любая красная строка — в отчёт с полным текстом.
- A2 `npm run desktop:build:extras` собирается. Если нет — полный лог ошибки (особенно `externalBin`, `resources`, Rust-компиляция `lib.rs`/`extras.rs`).
- A3 Установи собранный установщик. Убедись, что рядом с `TetraFree.exe` лежит `node.exe`, а в `resources\server\` — все `.mjs` (сверь с `server/`).
- A4 Временно убери Node из PATH (`where node` пуст) и запусти установленное приложение: статус сервера в заголовке должен быть «онлайн», процесс `node.exe` — дочерний у TetraFree, чёрного окна консоли нет. Закрой приложение — `node.exe` должен исчезнуть.

**B. Терминал (ConPTY, самое важное)**
- B1 Открой проект → терминал. Проверь, что в `%LOCALAPPDATA%\TetraFree\bin\` появился `conpty-*.exe`. Если нет — зайди на `http://127.0.0.1:3001/api/health` (после входа) и посмотри, почему `pty:false`; запусти компиляцию вручную: `csc /nologo /out:test.exe conpty.cs` на файле `.cs` из той же папки и покажи ошибки компилятора.
- B2 Работают: ввод и вывод, цвета, `cd`, Ctrl+C, стрелки/история в PowerShell, Tab-дополнение, `vim`/`less` (если есть git-bash), `npm create vite@latest` с интерактивным выбором, ввод пароля (`ssh`), Unicode/кириллица в выводе и в путях.
- B3 Изменение размера окна/панели меняет размер консоли (`mode con` или `$Host.UI.RawUI.WindowSize`). Длинные строки переносятся правильно.
- B4 Закрыть терминал → в диспетчере задач не остаётся `powershell.exe` и `conpty-*.exe`. Открыть 12+ терминалов → понятная ошибка, не падение.
- B5 Проверка отсутствия .NET csc: переименуй csc.exe (или запусти с `WINDIR` на пустую папку) → приложение должно не падать, а откатиться на обычный режим команд с понятным сообщением.

**C. Ключи API**
- C1 Добавь провайдера с ключом. Проверь: `%USERPROFILE%\TetraFree\secrets.json` существует, режим `"dpapi"`, значения — шифртекст (не содержат ключ). В DevTools (F12 в Tauri-режиме dev, либо браузер) `localStorage.getItem('tetrafree')` **не** содержит ключа.
- C2 Перезапусти приложение: ключ снова на месте (провайдер «ключ добавлен»), агент отвечает.
- C3 Удали провайдера → запись исчезла из `secrets.json`. «Стереть данные приложения» → ключи тоже удалены.
- C4 Остановленный сервер: ключ введён, а сервер выключен → ключ остаётся в localStorage (не теряется); после запуска сервера переезжает в хранилище.
- C5 Скопируй `secrets.json` на другую учётную запись/машину — расшифровать не должно получаться (ожидаемо: записи пропускаются).

**D. Проекты и папки**
- D1 Новый проект в папке с пробелами и кириллицей (`C:\Users\...\Мои проекты\тест 1`); выбор папки через «Обзор…» (диски C:, D:); открыть существующую папку со своим `.gitignore` (`node_modules`, `dist`, `*.log` не импортируются).
- D2 Удали папку проекта на диске, пока приложение открыто: проект не должен стираться, виден значок «папки нет на диске»; «Сменить папку…» и «Показать в проводнике» работают.
- D3 Внешняя правка файла в VS Code → меняется в приложении; правка в приложении → на диске. CRLF/LF не должны давать «изменён весь файл».
- D4 Git: статус, коммит выбранных файлов, ветки, blame, откат файла — на репозитории с кириллицей в путях и именах.

**E. Агент (через поддельную LLM и, если есть ключ, через настоящую)**
- E1 Сообщение → ответ стримится, создаётся `hello.txt`, выполняется `echo ok-from-shell`, вывод виден; можно принять/отклонить правки; остановка посреди ответа работает.
- E2 Ошибка модели (выключи fake-llm) → понятное сообщение, интерфейс не зависает.
- E3 Реальная модель (если есть ключ): «создай index.html с кнопкой» → файл на диске.

**F. Режим «Дизайн»**
- F1 Панель инструментов слева: Выбор (V), Рука (H), блоки (Shift+T, T, B, I, C, R, D), дублировать/удалить, сетка (G), планшет, телефон; подсказки с горячими клавишами; фокус с клавиатуры (Tab) виден.
- F2 Добавление блока, перетаскивание, ресайз, двойной клик по тексту, Undo/Redo, запись в `site/index.html`, внешняя правка файла обновляет холст.
- F3 Режимы Холст / Превью / Код; Превью запускает скрипты страницы.

**G. Фон и оформление**
- G1 Фон-изображение виден за прозрачными частями; плавно «дышит» и слегка двигается за курсором; свёрнутое окно — анимация на паузе (проверь загрузку CPU в диспетчере задач: в покое < 3% ядра).
- G2 Настройки → Оформление: «Фоновое свечение» выключает фон; «Меньше анимации» и системная «Показывать анимацию» останавливают анимации.
- G3 Светлая тема не ломает читаемость.

**H. Система (только `extras`-сборка)**
- H1 Значок в трее: показать/скрыть окно, выход. H2 Автозапуск вкл/выкл (проверь запись в автозагрузке). H3 Ctrl+Alt+N поднимает окно из любого приложения. H4 Закрытие крестиком сворачивает в трей, если так задумано.
- H5 SmartScreen: установщик не подписан — это известно, просто отметь.

**I. Устойчивость**
- I1 Закрой приложение «жёстко» (завершить задачу) во время записи → при запуске данные целы (есть автокопии в `TetraFree\backups`).
- I2 Порт 3001 занят другим процессом → приложение стартует и объясняет, что сервер недоступен.
- I3 Проект на ~2000 файлов (например, клон небольшого репозитория без `node_modules`) — интерфейс не лагает, синхронизация не зацикливается.
- I4 Меню Настройки → «Что нового» → «Скопировать диагностику» — приложи результат к отчёту при любой ошибке.

## 5. Правила работы
- Ничего не придумывай. Не смог проверить — пиши «⏭ не проверено: причина». Не угадывай результат по коду.
- Не правь код по своей инициативе, пока не закончил тестирование. Исключение — пункт A2/B1, если без правки нельзя двигаться дальше: тогда правь минимально, в отдельной git-ветке, и отдельно опиши правку.
- На каждый баг: ID, шаги воспроизведения (по пунктам), ожидалось / получилось, версия (`package.json`), ОС и сборка Windows (`winver`), логи/скриншоты, предполагаемая причина с путём к файлу и строкой, серьёзность (блокер релиза / серьёзно / мелочь).
- Секреты (ключи API, пароли, содержимое `secrets.json`) в отчёт не вставляй.
- Не удаляй пользовательские данные в `%USERPROFILE%\TetraFree` без копии.

## 6. Формат итогового отчёта (Markdown, по-русски)
1. **Вывод одной строкой:** можно ли отдавать команде сборку (да / да с оговорками / нет) и почему.
2. **Таблица** пунктов A–I: ID | статус | комментарий.
3. **Баги** списком по убыванию серьёзности (формат из раздела 5).
4. **Что не удалось проверить** и что нужно для этого.
5. **Топ-5 рекомендаций**, что чинить в первую очередь.
Сохрани отчёт в `docs/test-report-<дата>.md`.
