# Архитектура TetraFree

Один человек, один код — поэтому правила короткие и проверяются машиной (`npm run check`).

## Слои (зависимости идут только вниз)

```
screens / workspace / modals / design / components   ← UI (React)
        │
     agent/   ← движок агента: ход (turn), промпты, живой цикл
        │
     store/   ← состояние (zustand + immer + persist), действия по доменам
        │
     lib/     ← чистые функции и клиенты (git, backend, diff, merge3, usage…), без React и без стора
        │
     types.ts, data/   ← типы и сид-данные
```

- **`lib/`** — чистая логика. Если функция не трогает стор и DOM — она здесь и у неё есть `*.test.ts`.
  Новый алгоритм без теста в `lib/` не принимается.
- **`store/`** — единственный источник правды о состоянии. Компоненты не мутируют проект напрямую, только через действия.
- **`agent/`** — всё, что делает агент. UI зовёт `sendMessage`, `stopTurn`, `applyProposed` и т. п.
- **`server/`** — локальный сервер (`tetra-server.mjs`: git, файлы, PTY, бэкапы; `auth.mjs`: аккаунты и команды). Тесты рядом: `*.test.mjs`.

## Стор

| Файл                   | Что внутри                                                                                                                           |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `store/types.ts`       | `Persisted` (сохраняется), `UI` (временное), `Actions` (все мутации), `ModalState`                                                   |
| `store/defaults.ts`    | начальное состояние и настройки по умолчанию                                                                                         |
| `store/helpers.ts`     | `find`, `chatOf`, `tomb`, `uniqName`, `pickFile`                                                                                     |
| `store/persistence.ts` | что и как пишем в localStorage: `partialize`, `merge`, **`migrate`**, `PERSIST_VERSION`, защита от переполнения                      |
| `store/slices/*.ts`    | действия по доменам: `ui`, `projects`, `files` (файлы, корзина, версии, комментарии), `chats`, `docs`, `tasks`, `settings`, `memory` |
| `store/index.ts`       | сборка: `useStore`, селекторы (`useProject`, `getChat`, `toast`)                                                                     |

### Как добавить действие

1. Сигнатура в `Actions` (`store/types.ts`).
2. Реализация в подходящем слайсе — TypeScript заставит указать имя в `Pick<Actions, …>`.
3. Если действие меняет сохраняемые данные — подумай о миграции (ниже).

### Как поменять формат сохранённых данных

Пользователь хранит проекты в localStorage — потерять их нельзя.

1. Добавил необязательное поле — миграция не нужна, читай с `?? значение_по_умолчанию`.
2. Переименовал/перестроил — подними `PERSIST_VERSION`, добавь ветку в `migrate()` и тест в `persistence.test.ts`.
   Неизвестная версия **сбрасывается** к начальному состоянию — поэтому ветка обязательна.

## Движок агента (`src/agent`)

| Файл                               | Роль                                                                      |
| ---------------------------------- | ------------------------------------------------------------------------- |
| `engine.ts`                        | оркестрация: `sendMessage`, `runTurn`, живой цикл, проверка, права, откат |
| `turn.ts`                          | класс `Turn` (живые части сообщения) и `commitFiles` (итоговая версия)    |
| `projectfs.ts`                     | запись/удаление файлов проекта, чистка пустых папок                       |
| `prompt.ts`                        | история чата и системная инструкция для модели                            |
| `protocol.ts`, `llm.ts`, `live.ts` | формат ответа модели, запросы к провайдерам, живой режим                  |
| `queue.ts`, `ci.ts`                | очередь сообщений, пайплайны (настоящие команды через бэкенд)             |

## Стили

`styles/app.css` → `styles/components.css` (грузится позже и **перекрывает** первый при равной специфичности). Новое — в конец `app.css`; если правило «не применяется», сначала ищи дубль в `components.css`.

## Соглашения и проверки

- Форматирование — Prettier (`npm run format`), стиль в `.prettierrc.json`. Руками не выравниваем и не пишем строки по 200 символов.
- Линтер — ESLint (`npm run lint`): `any` запрещён, неиспользуемое — ошибка, `eslint-disable` только с причиной в комментарии.
- Типы: `tsc -b` проверяет и код, и тесты (`*.test.ts`).
- Всё вместе: `npm run check` (типы → линтер → формат → тесты). Тот же набор гоняет CI.
- Тесты добавляются в явный список в скрипте `test` (`package.json`) — новый файл без записи там не запустится.
- Версии: `x.y.Z` — исправления/внутренности, `x.Y.0` — новые функции, `X.0.0` — крупная переработка. Запись в `src/data/changelog.ts`, `CHANGELOG.md`, `ROADMAP.md`.

## Известный долг (честно)

- `engine.ts` всё ещё ~1000 строк: живой цикл, применение/откат правок и проверки живут вместе и делят состояние хода.
- В компонентах ~70 прямых вызовов `useStore.getState()` — часть логики стоило бы уйти в действия стора.
- Два CSS-файла с перекрытием; сервер (`tetra-server.mjs`) — один файл с маршрутами.
- Нет интеграционных тестов UI: проверка интерфейса — ручные прогоны в браузере.
